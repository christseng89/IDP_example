# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A full five-layer CNCF Internal Developer Platform (IDP) running on Docker Desktop Kubernetes, bootstrapped with a single script. It demonstrates Argo CD, Argo Rollouts canary deployments, Backstage portal, Prometheus/Grafana observability, and Kyverno policy enforcement across two Node.js microservices.

## Common commands

### Platform

```bash
# Bootstrap everything (~10–20 min first run)
bash scripts/install.sh

# If port 80 is occupied (common on Windows):
HTTP_PORT=9080 bash scripts/install.sh

# Tear down — use this instead of terraform destroy (handles Kyverno webhook deadlock)
bash scripts/teardown.sh

# Run the interactive stakeholder demo
bash scripts/demo.sh
HTTP_PORT=9080 bash scripts/demo.sh
```

Environment variables for `install.sh` / `demo.sh`:

| Variable | Default | Purpose |
|---|---|---|
| `HTTP_PORT` | 80 | nginx-ingress LoadBalancer port |
| `HTTPS_PORT` | 443 | nginx-ingress HTTPS port |
| `KYVERNO_MODE` | `Enforce` | `Enforce` or `Audit` |
| `SKIP_BUILD` | — | Skip Docker image build step |
| `DOCKER_MIRROR`, `K8S_MIRROR`, `GHCR_MIRROR`, `QUAY_MIRROR` | DaoCloud CDN | Registry mirrors for restricted networks |

### Services

```bash
# Build all Docker images (Docker Desktop shares the host daemon)
bash scripts/build-images.sh

# Lint a service
cd services/svc-alpha && npm run lint

# Test a service (npm install required — no lockfile committed)
cd services/svc-alpha && npm install && npm test

# Run a single test file or by name pattern
cd services/svc-alpha && npx jest src/app.test.js
cd services/svc-alpha && npx jest -t "GET /health"

# Run a service locally
cd services/svc-alpha && VERSION=v1 node src/index.js
```

### Rollout management

```bash
# Watch rollout progress
kubectl argo rollouts get rollout svc-alpha -n svc-alpha --watch

# Manually promote to next step (need to run twice for a full rollout)
kubectl argo rollouts promote svc-alpha -n svc-alpha

# Abort and rollback
kubectl argo rollouts abort svc-alpha -n svc-alpha
```

## Architecture overview

```

  outputs.tf            # Platform endpoint URLs

    platform/           # nginx-ingress, Kyverno, Crossplane
    observability/      # kube-prometheus-stack + Grafana canary dashboard ConfigMap
    gitops/             # Argo CD, Argo Rollouts, ArgoCD Application CRs, Kyverno ClusterPolicies
    backstage/          # Backstage helm_release + PostgreSQL 16 + all ConfigMaps/Secrets

  svc-alpha-app.yaml
  svc-beta-app.yaml

charts/
  svc-alpha/            # Helm chart: Rollout, Services, Ingress, AnalysisTemplate, NetworkPolicy, ServiceMonitor
  svc-beta/             # Same structure as svc-alpha

services/
  svc-alpha/src/        # app.js (Express app, exportable), index.js (server start), routes/v1.js, routes/v2.js, metrics.js, app.test.js
  svc-alpha/docs/       # TechDocs source (index.md) — served by Backstage TechDocs plugin
  svc-beta/src/         # Same structure as svc-alpha

backstage/
  app-config.yaml       # Backstage config (templatefile — variables substituted by Terraform)
  catalog/              # all.yaml, svc-alpha-catalog.yaml, svc-beta-catalog.yaml (inlined OpenAPI)
  scaffolder-templates/ # new-service/template.yaml

  teardown.sh           # Removes Kyverno webhooks first, then terraform destroy
  build-images.sh       # Builds svc-alpha:v1, v2, svc-beta:v1, v2

.github/workflows/
  ci.yml                # lint, test, docker build + Trivy scan, helm lint, terraform validate, yaml lint, deploy-gate
```

### Critical design decisions

**ArgoCD owns the Helm releases** — `selfHeal: true` means any direct `helm upgrade` is immediately reverted. To change a release, commit the values change and trigger ArgoCD sync:

```bash
sed -i 's/tag: v1/tag: v2/' charts/svc-alpha/values.yaml
git add charts/svc-alpha/values.yaml && git commit -m "Trigger canary: v1 → v2"
kubectl patch app svc-alpha -n argocd --type merge \
  -p '{"operation":{"initiatedBy":{"username":"demo"},"sync":{"revision":"HEAD"}}}'
```

**ArgoCD uses local file:// sources** — The repo-server mounts the host's `idp-local/` directory. Windows path `C:\Users\...\idp-local` is translated to `/run/desktop/mnt/host/c/users/.../idp-local` (Docker Desktop hostPath). Applications use `repoURL: file:///idp-local/charts/svc-alpha` — no external Git remote is needed.

**Two-phase Terraform apply** — `install.sh` works around a Windows Kubernetes provider crash (versions 2.38.0+ crash on parallel namespace creates):
- Phase 1: `parallelism=1`, applies only `kubernetes_*` resources
- Phase 2: normal apply for `helm_release` and `kubectl_manifest`

**Kubernetes provider** — uses `gavinbunney/kubectl` (NOT `hashicorp/kubectl`). Defined in all four module `main.tf` files.

**Image pullPolicy: Never** — Service images (`svc-alpha:v1/v2`, `svc-beta:v1/v2`) are built locally and never pushed to a registry. Docker Desktop shares the host daemon, so kubelet finds them via the local image store.

**Prometheus service name** — `prometheus-stack-kube-prom-prometheus.monitoring:9090` (release name `prometheus-stack` + kube-prometheus-stack chart naming convention). Used in `AnalysisTemplate` and Grafana data source.

**Canary rollout flow** — steps: setWeight 20 → pause (manual) → setWeight 50 → pause (manual; AnalysisTemplate runs in background) → setWeight 100. Two `kubectl argo rollouts promote` commands complete a full rollout. The AnalysisTemplate queries Prometheus for HTTP success rate ≥ 95% over 3 × 30s intervals; drops below 90% trigger automatic abort.

**Backstage token** — The Kubernetes plugin reads from `kubernetes_secret.backstage_k8s_token` (type `kubernetes.io/service-account-token`), created by Terraform and auto-populated by Kubernetes.

**Services are testable** — `src/app.js` exports the Express app without starting a server. `src/index.js` only starts the listener. Tests use supertest against the exported app.

### Canary ingress architecture

Each service has two Kubernetes Ingresses (stable + canary) and two Services (stable + canary). The Argo Rollouts controller updates the `nginx.ingress.kubernetes.io/canary-weight` annotation on the canary ingress to shift traffic.

### Backstage features

| Feature | How it works |
|---------|-------------|
| Catalog | `backstage-catalog` ConfigMap mounted at `/backstage/catalog/` |
| Kubernetes plugin | ServiceAccount token from `backstage-k8s-token` secret; `skipTLSVerify: true` (Docker Desktop) |
| ArgoCD plugin | Password from `backstage-argocd` Secret env var; connects to `argocd-server.argocd.svc.cluster.local` |
| TechDocs | `builder: local`, `publisher: local` — reads docs/ from pod |
| Scaffolder | `backstage-scaffolder` ConfigMap mounts `template.yaml`; skeleton fetch won't work without additional mounts |

## Security controls

- All pods: `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`
- Backstage ClusterRole: read-only, no `configmaps` (prevents secret exposure via ConfigMaps)
- Argo CD RBAC: `policy.default: role:readonly` (unauthenticated callers are read-only)
- NetworkPolicies: deny-all default + selective allow per namespace
- Kyverno: two `Enforce` policies (`require-version-label`, `require-security-context`) — controlled by `var.kyverno_enforcement_mode` (default: `Enforce`; set to `Audit` for development)
- Dependency versions pinned (no `^` caret in package.json)
- CI: `npm audit --audit-level=high` blocks on HIGH/CRITICAL dependency vulnerabilities (SOC2 CC8.3)
- CI: Trivy container scan on all four images blocks on fixable HIGH/CRITICAL CVEs (SOC2 CC8.3)
- CI: `deploy-gate` job requires manual reviewer approval via GitHub Environment `production` (SOC2 CC8.2)

### GitHub Environment setup (one-time)

Create the `production` environment in **Settings → Environments → New environment** and add at least one required reviewer. The `deploy-gate` CI job pauses until a reviewer approves, providing human approval evidence for SOC2 CC8.2.
